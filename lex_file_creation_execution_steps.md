
## Lex Practical – File Creation and Execution Steps

This document explains how to create the Lex (`.l`) file, generate the C (`.c`) file, compile it, and run the executable.

---

## 1. Create the Lex Program File

Create a file with the `.l` extension.

For example:

```text
comments.l
```

Open the file in VS Code and write the Lex program.

Save the file in the same project folder.

---

## 2. Create the Input C File

If the Lex program is designed to read a C source file, create another file with the `.c` extension.

For example:

```text
input.c
```

Add some C code containing comments:

```c
#include <stdio.h>

// Variable declaration
int a = 10, b = 20;

/*
   This is a
   multi line comment
*/

int main()
{
    // Addition
    int sum = a + b;

    printf("Sum = %d\n", sum); // Print result

    return 0; // End of program
}
```

Save the file in the same directory as `comments.l`.

---

## 3. Check the Files

Open the terminal in the project directory and run:

```bash
ls
```

You should have:

```text
comments.l
input.c
```

---

## 4. Generate the C File Using Flex

Run:

```bash
flex -o comments.c comments.l
```

### Explanation

- `flex` → runs the Lex/Flex lexical analyzer generator.
- `-o comments.c` → specifies the name of the generated C file.
- `comments.l` → input Lex program.

After running the command, a new file will be created:

```text
comments.c
```

Now the folder contains:

```text
comments.l
comments.c
input.c
```

---

## 5. Compile the Generated C File

Run:

```bash
gcc comments.c -lfl -o comments
```

### Explanation

- `gcc` → C compiler.
- `comments.c` → generated C source file.
- `-lfl` → links the Flex library.
- `-o comments` → creates an executable named `comments`.

After successful compilation:

```text
comments
```

will be created.

The folder now contains:

```text
comments.l
comments.c
comments
input.c
```

---

## 6. Run the Executable

Since the program reads the C source file from the command line, run:

```bash
./comments input.c
```

Here:

- `./comments` → runs the executable.
- `input.c` → C source file given as input.

---

## 7. Expected Output

The program extracts the comments from `input.c`.

Example:

```text
----- Extracted Comments -----

// Variable declaration

/*
   This is a
   multi line comment
*/

// Addition

// Print result

// End of program

Total Single Line Comments : 4
Total Multi Line Comments  : 1
```

---

## 8. Complete Command Sequence

Once `comments.l` and `input.c` have been created, the complete sequence is:

```bash
flex -o comments.c comments.l
gcc comments.c -lfl -o comments
./comments input.c
```

---

## 9. Important: Why Use `-o`?

The command:

```bash
flex -o comments.c comments.l
```

creates:

```text
comments.c
```

instead of the default:

```text
lex.yy.c
```

Similarly:

```bash
gcc comments.c -lfl -o comments
```

creates:

```text
comments
```

instead of the default:

```text
a.out
```

This is useful when working with multiple Lex practicals because each practical can have its own generated C file and executable.

---

## 10. Recommended Folder Structure

For this practical:

```text
TOC-and-CD-Practicals/
│
├── comments.l       # Lex source program
├── comments.c       # C file generated by Flex
├── comments         # Executable
└── input.c          # Input C source file
```

For another practical, use different names.

Example:

```text
TOC-and-CD-Practicals/
│
├── caesar.l
├── caesar.c
├── caesar
│
├── comments.l
├── comments.c
├── comments
│
├── prog.l
├── prog.c
├── wordcount
│
└── input.c
```

This prevents generated files and executables from overwriting each other.
